# dsh-rewind

DSH Web 插件，给每条用户消息加上「撤回」和「编辑」两个按钮。

- **撤回** —— 把对话回退到这条消息**之前**：从该处之前的回合边界分叉出新会话，并归档原会话，可撤销。
- **编辑** —— 改掉这条消息后从该处重新开始：分叉出新会话，把改好的文本送进输入框并发送。

> **为什么是「分叉 + 归档」而不是「删除」**
> DSH 的会话日志是追加式的（事件从 seq 0 起连续、从不重写），官方没有原地删除或截断消息的原语。
> 「从回合边界分叉」是官方唯一的等价回退能力，与内置的「分支」按钮走同一条链路；
> 原会话被归档而不是销毁，所以随时可以恢复。

## 安装

```bash
dsh plugin --profile <profile> add <本仓库路径>
```

然后重启 `dsh web`（插件图的组合变化不走热更新），并刷新页面。

> 构建产物 `lib/` 已随仓库入库：git / npm 源安装默认不执行构建脚本，产物必须在包内。

## 使用

两个按钮出现在用户消息的动作行里，与内置的复制按钮**同一行**。

| 操作 | 效果 |
|---|---|
| 撤回 | 从这条消息之前的最后一个回合边界分叉 → 切到新会话 → 归档原会话 |
| 编辑 | 弹窗回填原文 → 确认 → 分叉 → 文本送进新会话输入框并自动发送 |

行为细节：

- 显隐跟随内置动作行：**最后一条**用户消息常驻可见，更早的消息把鼠标移上去才一起出现。
- 成功不弹提示；原会话可从「未归档会话」恢复。
- 只有真正出问题时才提示（内容没送进新会话 / 发送被拒），这类提示带「撤销」入口。
- **首条消息只提供「编辑」**，不提供「撤回」——撤回它等于清空并归档整段对话。
- **回合中途插话**（steering）时两个按钮置灰，鼠标移上去可看到原因：无法精确回退到它之前。
- 分叉出的子会话**标题与原会话一致**，不会追加递增序号。
- 分叉出的子会话**不继承**模型、挡位等会话级选择。

## 架构

插件分成两半，各自只有一个入口：

| 层 | 文件 | 职责 |
|---|---|---|
| 宿主半 | `src/index.js` | 空的 `apply()`，只让插件进入配置树 |
| 浏览器半 | `src/client/index.jsx` | 全部交互逻辑 |

浏览器半的挂载方式：

- DSH 没有「用户消息动作」插槽，唯一可用的挂载点是 keyed 槽 `conversation.chat.node`。
  插件为 `user` 与 `steering` 两个 key 各注册一个**影子渲染器**。
- **不重画气泡**：内置渲染器没有导出，但能从原始的槽条目里读到它的组件引用，
  于是把它**原样**渲染，只在自己的 Fragment 里追加按钮——视觉零退化，也不会拖住内置渲染器升级。
- **按钮并进内置动作行**：靠 React portal 把按钮渲染进内置动作行，从而复用内置的显隐规则。

## 实现方法

### 1. 按钮落点：结构优先 + 横向行闸门

渲染槽位时宿主会给每个槽包一层 `div[data-slot][style="display:contents"]`，
所以拿「内置渲染器根」必须比直觉多下钻一层。定位动作行按两条策略，且都必须通过闸门：

- **结构策略**：内置根里最后一个「含 `<button>` 且不是本插件产物」的直接子元素；
- **兜底策略**：内置复制按钮的父元素（Tooltip 只注入 ref 与事件，不额外插 DOM 层）。

**闸门**要求目标同时满足：不是本插件节点、且是横向行（`display:flex` + `flex-direction:row`）。
少了这道闸门就会把按钮放进一个纵向容器，表现为「按钮还是单独占一行」。
两条策略都没通过时退回「自己一行」，功能不受影响。

**定位与 portal 代码绝不抛错**：影子覆盖的 entry 一旦渲染抛错，宿主会把它整个退休，
表现就是「消息正常、按钮整体消失」。

### 2. 撤回锚点：取权威回合边界，不做推断

分叉 API 的边界语义是「该 seq 之后（含）第一个回合结束事件」，落在未闭合回合内则不可用。

所以「回到这条消息之前」就是取**上一回合的回合结束 seq**，而这个值不需要推断：
chat 快照里已经按回合结束事件构建好了映射，直接按回合号取即可精确命中。

**不能用「回合开始 seq − 1」这类看起来显然的兜底**：回合开始与上一回合结束之间还夹着其它事件，
`start − 1` 并不是回合边界，「第一个 ≥ 它的回合结束事件」会落到**本回合**末尾——
撤回会静默切错位置，而原会话已经被归档。

因此拿不到权威锚点时，撤回按钮**直接置灰**并说明原因，而不是给一个可能切错的按钮。

### 3. 切会话、归档与空白会话

```
分叉或新建子会话
  → uiWorkspace.openSession(childId)        // 切换导航
  → uiWorkspace.archiveSession(sessionId)   // 之后再归档
```

- **归档放在切会话之后**：归档会清掉「当前选中项」，先切再归档才安全。
- **空白会话优先用 `workspaceId`**（而不是 `cwd`）：只给 `cwd` 时新会话可能不挂在任何
  Workspace 节点下，侧栏里找不到，输入框也会因为拿不到 workspace 标题而不可用。
- **不传 `increaseTitle`**：它会给继承来的标题追加递增序号，每撤回一次就再涨一位。

### 4. 改写内容投送：走与视图无关的输入接口

打开新会话后 UI 需要一两 tick 才就绪，所以先等绑定，再拿**该会话常驻**的输入接口写入草稿。

**不能用「composer 槽挂载时回填」**：空会话渲染的是 hero 形态，而 composer 槽只在 composer
形态下才渲染——挂在它上面的回填器根本不会挂载，表现为「编辑首条后草稿不出现」。

写入后**读回核对**（读快照里的草稿值），确认进去了才自动发送；投送失败时**不发送**，
提示手动发送并保留「撤销」入口——不留半成品，也不丢退路。

### 5. 不可用状态用 `aria-disabled`，不是 `disabled`

浏览器不会给 `disabled` 元素发 hover 事件，那样「为什么不能点」的提示永远弹不出来。
改用 `aria-disabled` 并去掉点击处理，鼠标移上去仍能看到原因。

### 6. 兼容性：三道防线

影子覆盖的 entry 若渲染抛错，宿主会把**整个 entry 退休**并把赢家换回内置渲染器；
更麻烦的是被退休的 entry 仍留在原始条目表里，所以拿它判断「我赢了吗」永远得到「是」。

1. **图标按名探测**：primitives 的导出名会随版本变化，静态绑定旧名会拿到 `undefined`，
   React 直接抛错。按候选名链探测，全都没有就回落到自绘符号，**永不把 `undefined` 递给 React**。
2. **自带错误边界**：渲染期的抛错在本插件内部按级退化，宁可这条消息不渲染按钮，
   也绝不让错误穿透到宿主去换掉整个 entry。
3. **自愈看赢家投影**：判断「是否赢得槽位」要读宿主投影后的赢家视图（它会跳过被退休的 entry），
   而不是原始条目表；万一仍被退休，dispose 后重新注册把它救回来。
   只有「取内置渲染器」这一步必须读原始条目表——内置渲染器正是被遮蔽的那一个。

注册顺序与优先级不完全可控，所以影子覆盖带**顺序自愈**：注册后自查是不是赢家，
不是就有限次重注册，抢不到就安静退让并打一次性诊断，绝不抛错。

### 7. 客户端 bundle 的依赖边界

客户端 bundle 只能 require 宿主**静态共享模块表**里的包。其它内部包只能做类型引用——
运行时 import 会打进第二份实例（第二份 React 会直接报错）。本插件的浏览器半只依赖
React 与 UI primitives 两处，仓库的门禁脚本会强制这条边界。

## 开发

```bash
pnpm install                    # 或 npm install，只装 esbuild
pnpm run bundle                 # src/ → lib/
pnpm run gates                  # 一致性门禁（名称、合同、共享模块边界）
node scripts/smoke-require.mjs  # 非可视化冒烟（用假 React 驱动真实产物）
```

> 改完构建产物**不需要重启 `dsh web`**：宿主会轮询插件客户端产物的修改时间与大小，
> 有变化就重载 bundle，**刷新浏览器页面**即可拿到新版本。
> 只有插件图组合变化（增删插件、改 profile）才需要重启 web。

### 目录

```
src/index.js               宿主半
src/client/index.jsx       浏览器半：全部逻辑
scripts/build.mjs          打包
scripts/gates.mjs          一致性门禁
scripts/smoke-require.mjs  非可视化冒烟
lib/                       构建产物（随仓库入库）
docs/plan.md               设计与决策追踪
```

冒烟脚本会驱动真实产物，断言槽位注册参数、组件树结构、动作行的横向布局、
「定位内置动作行」的爬 DOM 逻辑、各类降级分支、撤回传给分叉的锚点与归档顺序、
改写内容的投送与自动发送、以及影子覆盖的顺序自愈与兼容性防线。
它**不能**替代浏览器验收。

## 已知限制

- 分叉不是删除：原会话被归档而非销毁（日志是唯一真相）。
- 撤回只能切在**回合边界**上，回合中途插话无法精确回退。
- 子会话不继承模型、挡位等会话级选择。
- 编辑总是自动发送。
- 「与复制按钮同行」依赖内置动作行的两条结构事实；宿主改结构时会自动退回「自己一行」，
  功能不受影响，但会变成两行显示。
